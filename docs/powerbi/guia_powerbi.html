Guía Power BI — Tablero DatosVivos

Conexión · Diccionario de datos · Sugerencias de visualización · Mockup · Changelog  |  V3 — 2026-06-08

El tablero se alimenta de dos archivos CSV públicos (recomendados): datasets_decisor.csv (29 columnas curadas, 1 fila por dataset) y entities_decisor.csv (14 columnas, 1 fila por entidad publicadora con KPIs derivados). Cubren 23.854 datasets de 4 fuentes federadas: Socrata datos.gov.co (nativos + federados), CKAN territoriales (Bogotá / Cali / Valle) y DCAT MEDATA (Medellín). Sin PII. Power BI lo consume y refresca sin gateway (Postgres vive tras VPN y la VM es Linux). Modo recomendado: Import. La frescura del dato se sirve por header HTTP Last-Modified (RFC 7231).

Los endpoints legacy /datasets.csv y /entities.csv (V2) siguen vivos durante 2–4 semanas para coexistencia. Ver §5 Changelog para la guía de migración.

1.2 Conectar (Power BI Desktop)

  1. Inicio → Obtener datos → Web.
  2. Pegar https://datosvivos.co/api/v1/dashboard/datasets_decisor.csv.
  3. Autenticación: Anónima. Nivel de privacidad: Público.
  4. Modo de conectividad: Import. Cargar.
  5. Verificar tipos: fechas como Fecha/hora; números (download_count, page_views_total, row_count) como Número entero.
  6. (Opcional) Repetir con /entities_decisor.csv como segundo origen para la página por entidad.

1.3 Publicación y refresco automático

  • Publicar a Power BI Service → Publicar en la web (hace el tablero público; aceptable porque no hay PII).
  • Programar actualización (Scheduled Refresh) diaria sobre la fuente Web — no requiere gateway por ser URL anónima. (Suele exigir licencia Pro.)
  • Frescura por header HTTP: cada respuesta CSV incluye Last-Modified (RFC 7231) con MAX(last_refreshed_at) del catálogo. Power BI puede leerlo con Web.Contents(...)[Response.Headers] en M, sin necesidad de columna por fila. Útil para detectar fuentes stale.
  • Cadena de frescura: Socrata + CKAN + DCAT → ETL diario (05:00 UTC) + harvesters semanales (lunes) → Postgres → CSV decisor → refresh Power BI.

1.4 Reglas del modelo

  • Scoping por entidad: slicer sobre entity_name (99,6% poblado, mejorado desde 90,7% pre-Hito R). NO usar entity_abbrev (sigue esparso, ~10%).
  • Slicer crítico acceso_datos: default a directo para que los KPIs midan solo lo consultable como tabla (8.424 nativos). Ofrecer control para ver requiere_herramienta (1.207 con CSV externo: MEDATA, CKAN) o solo_metadatos (8.788 federados sin CSV declarado, mayoría IGAC). Sin este filtro, los conteos se inflan con cobertura no-tabular.
  • Filtro complementario es_federado: split nativo vs federado en el mismo eje (8.424 vs 15.430). Útil para comparar la salud del catálogo Socrata vs el universo CKAN/DCAT.
  • Toggle útil/administrativo: filtrar quality_flag — por defecto mostrar útiles (vacío); ofrecer ver admin_only (Ley 1712, ~12% del catálogo total) con un control.
  • Rollups por entidad sin DAX: usar entities_decisor.csv que ya trae pct_verdes, n_datasets_directos y n_datasets_federados calculados. Elimina ~3 medidas DAX por página. Si solo usas datasets_decisor.csv, el % verde sigue funcionando con DAX: % verde = DIVIDE(CALCULATE(COUNTROWS, status="verde"), COUNTROWS).

5. Changelog V2 → V3 (2026-06-08)

5.1 Resumen ejecutivo

Entre V2 (2026-05-25) y V3 (2026-06-08), el catálogo casi triplicó su tamaño (8.404 → 23.854 datasets) por la incorporación de portales municipales (CKAN Bogotá/Cali/Valle) y MEDATA Medellín (DCAT JSON-LD), y la cobertura curatorial subió drásticamente en columnas que el V2 dejaba en bajo porcentaje. Se liberaron dos vistas paralelas _decisor con menos columnas y mejor calidad para que el tablero del Director no muestre datos ambiguos. Los endpoints legacy del V2 siguen vivos para permitir migración gradual del .pbix existente.

5.4 Cómo migrar el .pbix existente

  1. En Power Query (modelo M), cambiar el origen del primer Web.Contents: /datasets.csv → /datasets_decisor.csv.
  2. Renombrar referencias en queries y visuales para las 5 columnas eliminadas: usar el mapping de la tabla 5.3 ("Columnas eliminadas").
  3. Reemplazar license → license_id en cualquier slicer o tarjeta de licencia. El vocabulario controlado da gráficos más limpios.
  4. (Opcional pero recomendado) Agregar segundo origen /entities_decisor.csv con relación entity_id 1:N a datasets_decisor.csv. La página por entidad usa pct_verdes directo → elimina ~3 medidas DAX.
  5. Si una visualización mostraba last_refreshed_at como columna, leer del header HTTP en M: Web.Contents(url, [ManualStatusHandling={304}])[Response.Headers]{"Last-Modified"} y exponer como medida.
  6. Validar slicers nuevos: acceso_datos default a directo (esconde 8.788 federados no-tabulares) y es_federado como filtro complementario.
